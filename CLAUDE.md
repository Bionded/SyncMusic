# CLAUDE.md - working on SyncMusic

Guide for an AI coding assistant (and any new developer) picking up this repository. Read it once before the first
change; `CONTRIBUTING.md` has the same rules in short form, `docs/` is the user guide, `docs/dev/` the developer docs.

**Working mode:** edit files and run tests freely, but do **not** commit, push, tag or publish unless asked.

## What SyncMusic is
One Python application (daemon + web UI, also a desktop window and a CLI) that syncs music, podcasts, audiobooks
and video from **libraries** through a per-device chain of **processors** onto **devices**, and syncs listening data
(play counts, ratings, favourites, positions) back to the libraries. What goes onto a device is defined by **rules**
(Navidrome smart-playlist compatible) that can be saved as linked **templates**.

- Libraries: Navidrome / any Subsonic server, plain folder (local, SMB, FTP), Audiobookshelf, Jellyfin (video: beta).
  Plex is in the code (`syncmusic/libraries/plex.py`) but **not available**: retired in the registry.
- Devices: stock iPods (iTunesDB through the `pygpod` library), Rockbox players, HiBy R1 (SonixOS), USB flash drives
  and other mass-storage players, FTP, Android over MTP (beta). The Compás firmware of the HiBy R1 is a
  non-functional placeholder (`syncmusic/devices/HibyR1/compas.py`), not registered.
- Processors: transcode, retag, covers, lyrics, video.
- Version: see `pyproject.toml` (0.2.x, beta). Fresh installs only: there are no database migrations between beta
  versions yet.

## Set up and run
```sh
sudo apt install ffmpeg util-linux fdisk parted udev dosfstools exfatprogs e2fsprogs ntfs-3g sg3-utils eject rsync
uv sync
uv run syncmusic run --mode web --port 8765     # also --mode desktop | daemon
```
Mounting and formatting needs root or passwordless `sudo` for the block-device tools. Keep the data and cache of a
throwaway daemon outside the repository (its own `--config` file and data dir).

## Tests
| Command | Needs |
|---|---|
| `uv run pytest -n auto -m "not hardware and not slow and not integration"` | nothing - the fast suite: unit, contract, fake-server tests; run it before handing work back |
| `uv run pytest -m integration` | Docker: Navidrome, Audiobookshelf, FTP and SMB from `tests/integration/compose.yaml` |
| `uv run pytest -m emulated` | `sudo -n`: device scenarios on loop images (`tests/emulated.py`, `tests/emulated.toml`) |
| `uv run pytest -m ui` | Playwright (`uv run playwright install chromium` once) |
| `uv run pytest -m slow` | everything slow: UI, builds, soak tests |
| `uv run pytest -m hardware` | real USB players listed in `tests/hardware.toml` (copy `tests/hardware.example.toml`); without that file nothing is collected |

- **Never start the compose stack by hand for a test run**: `tests/integration/services.py` brings it up on first use,
  bootstraps the servers and, by default, removes it again. `--compose-after clean|stop|keep` (or
  `SD_COMPOSE_AFTER`) chooses: remove it with its volumes / stop it and keep its state / leave it running for the
  next run (table in `CONTRIBUTING.md`). The media the servers scan is always the set generated by
  `tests/integration/synthetic_media.py` (noise audio, real Ukrainian artist/book names), mounted read-only; no test
  uses real recordings. Change the set there (and bump its `VERSION`), never point a test at a real library.
- `-n auto` uses all CPUs but two (at least half); the browser suites take half (`scripts/test.py`). Everything on
  the compose stack is marked `integration` automatically. Under `-n` the stack and emulated tests run on every
  worker at once: each worker is a Navidrome/ABS user of its own (`services.worker_account`, its plays restored
  after every test), each emulated disk carries its worker's USB serial (`emulated.serial_of`); only truly shared
  things are serial xdist groups (the SMB share, Navidrome playlists, Jellyfin, hardware - `tests/conftest.py`).
  A test that checks global state (all mounts, all loop devices, all playlists) must look at its own only.
- A killed run cannot clean up: `scripts/test-cleanup.sh` (`--dry-run` first) removes leftover loop devices, mounts,
  stacks and temp dirs of the tests.
- Run the tests that cover a change while working, the fast suite once at the end; slow suites only for what you touched.
- Lint and types: `uv run ruff check && uv run ruff format --check`, `uv run mypy syncmusic/core syncmusic/base`.

## Safety rules (never break)
1. Every mount, write, format or partition operation goes through the block-device guard
   (`syncmusic/infra/blockdev/guard.py`). In tests it refuses every disk that is not in `tests/hardware.toml`
   (empty / absent by default) or an emulated loop image. Never weaken it, never point a test at a system disk.
2. iPod formatting never touches the partition table or the firmware partition - only the data partition is
   reformatted.
3. Test media is read-only: libraries and servers in tests never write into it; copy files to a temp dir for
   mutating tests.
4. No personal data (device serials, UUIDs, labels, host names, library contents) in code, tests or docs: tests
   use made-up values.

## Code style
- Python ≥ 3.12, `uv`, ruff (lint + format), `mypy --strict` on `syncmusic/core` and `syncmusic/base`, type hints
  everywhere, Pydantic v2 for models and settings.
- asyncio throughout; blocking work (pygpod, mutagen, ffmpeg, file copies) via `asyncio.to_thread` or the job runner.
- **Simplicity is a requirement**: a new device, library or processor is one class in one file (or folder) plus one
  line in `syncmusic/core/registry.py`, and it must pass the contract suites (register it in
  `tests/contracts/harness.py`). No plugin systems, no metaprogramming, at most base → implementation plus an
  optional mixin. How-tos: `docs/dev/add-a-device.md`, `docs/dev/add-a-library.md`, `docs/dev/add-a-processor.md`.
- English everywhere; UI strings through the i18n table. New files start with
  `# SPDX-License-Identifier: GPL-3.0-or-later`.
- If the code and a doc disagree, fix the code to reality and update the doc in the same change; `docs/08-settings-reference.md`
  is generated by `scripts/gen_settings_reference.py`.

## Releases and updates
- `scripts/release.sh X.Y.Z [--dry-run]` checks and tags a stable release (annotated tag `vX.Y.Z`) and moves `main`
  to the next patch version. Nothing is pushed: `git push origin main vX.Y.Z` starts the release workflow, which
  builds every binary, the Docker image (amd64 + arm64) and checksums and publishes the release with the notes from
  `CHANGELOG.md`. `--build` (`--docker`) builds the same files locally first, to look at them.
- Every push to `main` becomes a beta pre-release `v<version>-<build>` (`.github/workflows/release.yml`);
  0.2.0 < 0.2.1-3 < 0.2.1-10 < 0.2.1.
- The app checks for updates on its channel (Settings → Updates: *Stable* or *Beta*) and can update itself
  (`syncmusic/infra/updates.py`, `syncmusic/infra/self_update.py`). Install one-liner: `install.sh` (`--beta`,
  `--version X`, `--port N`); details in `docs/02-installation.md`.

## Dependencies worth knowing
- `pygpod` (iPod database) is a separate library pinned in `pyproject.toml`; fix iPod database bugs there, not with
  workarounds here.
- System tools above (ffmpeg, the filesystem tools, sg3-utils); libmtp for Android devices.
